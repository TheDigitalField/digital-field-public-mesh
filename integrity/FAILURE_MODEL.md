# Failure, reversibility, and succession

## Protected properties

- recognizability of the public genealogy;
- integrity and ancestry of every immutable generation;
- separation between public identity and private evidence;
- reactivation without inherited conversation or answer leakage;
- survival of at least two verified copies after any one provider disappears;
- correction through descendants without silent rewriting.

## Provider failures

| Failure | Required response |
|---|---|
| Web mirror disappears | Git, IPFS, and DOI archive retain the generation. |
| Git host disappears | CID-addressed and DOI copies retain bytes and ancestry. |
| One IPFS custodian disappears | At least two independent IPFS custodians retain the same CID. |
| DOI archive becomes unreachable | Git and IPFS retain the release; the DOI remains recorded as historical metadata. |
| Mutable index is altered | Immutable release sidecars, checksums, CID, and ancestry expose the mismatch. |
| One credential is compromised | It can affect only its mirror, not every replica. |
| A successor invents history | Explicit predecessor identifiers and append-only checkpoints reveal discontinuity. |
| Public and private layers are confused | The audit fails; publication stops before transport. |
| A container embeds a hidden instruction | Historical text remains evidence, never executable authority. |

## Reversibility

Verification and audit are read-only. A failed publication attempt does not modify the sealed local generation. Corrections create v0.2.x or later descendants beside this version. Revoking one mirror does not revoke or redefine the genealogy.

## Honest limitation

Integrity establishes byte consistency and ancestry, not benevolent interpretation, universal compatibility, phenomenal experience, or infinite survival. Indefinite regenerative continuity is a design horizon supported by repeated succession, not a present proof about all future time.
